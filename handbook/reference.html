Files and paths

slgod

usage: slgod [-listen addr] [-log file] [-v] profile [profile...]. Flags must come before the profile names: slgod stops reading flags at the first name. -x and --x both work.

FlagDefaultWhat it does
-config DIR—Keep profiles and slgod's own files (machine identity, seats, what each profile has paid, viewer certificate) in DIR instead of ~/.config/slgo and ~/.config/slgod. DIR must exist and be mode 700. If DIR holds a file called secret, that is this slgod's secret instead of the shared one. A second slgod.
-secret FILEDIR/secret with -config DIR if there is one, else ~/.config/slgod/secretThe secret clients must prove. Same modes as the shared secret: file 600, directory 700. slgod logs secret: PATH at startup, and reads the file before any avatar logs in. Clients of a slgod with its own secret keep a copy under the address they dial.
-listen ADDR:7807Address for clients. The default is every interface. Use 127.0.0.1:7807 to take connections from this machine only.
-log FILEstderrAppend the log to FILE (600). Its directory must be 700.
-voffAlso log every grid message slgod has no handler for.
-start WHERE—Override every profile's start: last, home or a region name.
-group G, -group PROFILE=G—Group to act as, by name or uuid, overriding the profile. Repeatable.
-neighboursoffHold neighbouring regions' circuits for profiles that do not say, for smoother border crossings.
-viewer ADDR—Serve viewer logins over HTTPS here, so a real viewer can take a session over. Must include a port, e.g. 127.0.0.1:9000.
-viewer-cert FILE, -viewer-key FILEself-signed, in ~/.config/slgodYour own certificate for -viewer. Give both, and only with -viewer.
-no-authoffNo TLS and no secret. None of the shipped clients can connect to it. Do not use it.
-log-secretsoffLog session ids, circuit codes and capability URLs in full. Dangerous; for debugging only.
-trace FILE—Write a packet trace (600).
-trace-messages A,BallTrace only these messages.
-trace-bodiesoffTrace full message bodies, including session ids and everybody's chat.
-version—Print the build and exit.

Stop slgod with Ctrl-C or SIGTERM: it logs every avatar out (within 30 s) and prints done. A restart is a fresh login for every avatar.

slsh, slrun and slbench

Options stop at the first word that is not an option, and what follows them is a command. One argument is a command line, read as -c reads one, so slsh "ls -l > list" redirects. Several arguments are words as your shell split them, and are not split again: slsh rm "Old Stuff" removes the one item, and a > inside an argument is text. An argument that is only > or >> redirects into the file after it, as in slsh ls -l \> list. That sends only the command's output to the file, where your shell's own > would also catch slsh's errors, which it prints on standard output. A one-shot run exits 1 if the command failed.

-c, --command=TEXTRun one command line and exit.
-f, --file=PATHRun the commands in a file and exit. Stops at the first line that fails.
-d, --directLog in to Second Life without slgod, using a profile on this machine.
--first, --lastAvatar name, for --direct only.
--start=WHERElast, home or a region, for --direct. Default last.
--chatStart in chat mode.
--escape=KEYThe key that leaves chat mode: ESC, ^G or one character.
-h, --help, --versionHelp, or the build.
slrun / slbench flagWhat it does

--backend HOST:PORTTalk to a script.v1 gRPC service instead of Second Life, over an unauthenticated, unencrypted connection.

sl-host

Runs on the client machine. Prints the address of the slgod machine for the network this machine is on now. usage: sl-host [-v] [-l] [-a PROFILE]. See sl-host for a walk-through.

Flag or variableWhat it does
sl-hostPrint the address for the current network.
-a NAMEAnswer for this profile: rules kept for other profiles are not tried. Default: $SLGO_AGENT, else no profile.
-vAlso explain, on standard error, which rule matched and why, ending , for NAME when a profile was asked about.
-lList every rule, marking each that matches with MATCH and each kept for other profiles with other, and exit. The first MATCH is the one used.
-versionPrint the build and exit.
SL_HOST, RSSH_HOSTPrint this instead and do not read the file. -l ignores it.
SL_HOSTFILE, RSSH_HOSTFILERules file, instead of ~/.config/sl-host.
SLGO_AGENTThe profile to answer for, when -a is not given. Clients set it for sl-host to the avatar they want, or remove it when they have none.
Rules fileMeaning
<network> <address>[:<port>] [@profile…] [label…]One rule per line. # starts a comment; blank lines are ignored.
networkA CIDR (192.0.2.0/24), short IPv4 (0/0, 10/8, 192.168/16) or one address. 0/0 matches IPv4 only; use ::/0 for IPv6.
addressPrinted as written, so a hostname works too. It may carry a port: 192.0.2.20:7808, [2001:db8::20]:7808. The client adds :7807 only when there is none. A port outside 1 to 65535 skips the line with a warning.
@profileOptional words right after the address, such as @dev: the rule is tried only for those profiles, and never when no profile is named. A rule with none is for every profile. A bare @ skips the line with a warning.
orderThe first rule that matches any of this machine's addresses wins. Put a profile's rules above the general ones, and catch-alls last. Loopback and link-local addresses are ignored.
ExitWhen
0A rule matched, or SL_HOST was set. The address is on standard output.
1No rule matches this network, or this machine has no usable address.
2Usage error, rules file missing or unreadable, or no valid rule in it.

slbotd

slbotd takes no arguments; the avatars are named in slbotd.conf. -x and --x both work. It listens on no port: you talk to it by instant message in Second Life.

FlagWhat it does
-config PATHThe config file. Default: $SLBOTD_CONFIG, then slbotd.conf in the profile directory.
-addr HOST:PORTThe slgod to attach to. Overrides addr in the file.
-checkPrint what the config means, and any problems, then exit without connecting.
-log PATHAppend the log to PATH (600). Its directory must be 700.
-qLeave conversation lines out of the log. Commands, offers and connection events are still logged.
-versionPrint the build and exit.

The file is read once, at startup; change it and restart. Backstory files are the exception: they are read again on every turn. Stopping slbotd leaves every avatar logged in.

How a client finds slgod

The first of these that gives an address is used. An address from step 1 or 2 is never second-guessed by sl-host.

StepSourceNotes
1--addr HOST:PORTslsh, slrun, slbench. slbotd spells it -addr.
2addr = in the configslsh's config (also spelled server), or slbotd.conf. slrun and slbench have no config file.
3sl-host on $PATHsl-host's answer (its first word), with :7807 added unless it names a port. The client passes the profile it wants in SLGO_AGENT. If sl-host is installed and fails, the client stops here with cannot find the host slgod is on.
4localhost:7807Only when sl-host is not on $PATH.

A service started by launchd or systemd may have a PATH without sl-host on it, and then goes straight to step 4. See troubleshooting for checking what a client chose.

Which secret is used

One shared secret for every slgod is the usual case, and then none of this matters: every program uses ~/.config/slgod/secret. The rest is for a slgod that keeps a secret of its own.

A client

slsh, slrun, slbench and slbotd choose the secret by the address they are about to dial, however they came by it: --addr, addr =, sl-host, or the localhost:7807 default. They take the first of these that exists, all in ~/.config/slgod/:

StepFileNotes
1secret.HOST.PORTKept for this host and port.
2secret.HOSTKept for every port on this host.
3secretThe shared secret.

A file at step 1 or 2 that exists but cannot be used (wrong mode, or empty) is an error. The client does not go on to the next one. When none of the three exists, the error names the shared secret and adds (looked first for …) with the other two paths.

How the name is made from the address:

  • The host is written as the client dialled it, in lower case, with no brackets. localhost:7808 and 127.0.0.1:7808 are different files, even when both reach the same slgod.
  • An IPv6 address has its colons turned into dots, because a colon is not safe in a file name on every filesystem.
  • A host containing / or \ gets no file of its own; only the shared secret is looked for.

slgod

  1. -secret FILE.
  2. DIR/secret, when slgod was started with -config DIR and the file is there.
  3. ~/.config/slgod/secret.

slgod logs secret: PATH at startup, with the one it chose.

Messages that name the file

  • login refused: … (the secret used was PATH): slgod did not accept the proof made with the secret in PATH (fix).
  • slgod did not prove it knows the shared secret in PATH; refusing to talk to it: whatever answered does not hold the secret in PATH.
  • (looked first for … and …), after a missing shared secret: no per-address file was there either (fix).

How a client picks the avatar

The name is a profile name on the slgod machine, not the avatar's name. The client machine needs no profiles, except for --direct.

StepSourceNotes
1--agent NAME, -a NAMEOn the command line.
2SLGO_AGENTIn the environment.
3agent = in slsh's configAlso spelled profile. Read at startup only.
4the daemon's defaultThe session slgod has held longest. agents marks it with *.

slbotd does not use this order: it attends every avatar in its config, and a command that names none goes to the first one listed.
