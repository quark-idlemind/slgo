Reference · the code

Go packages

The documentation of every Go package in slgo, a page each, as go doc makes it from the comments in the source. pkg.go.dev cannot show them while the repository is private, so the handbook carries them.

Where to start

A program of your own needs sl. It is the layer that knows the protocol: you call Say, Move or GiveToAvatar on a session, and it returns once it has seen the thing happen. Its methods take and return a few types from msg, chiefly UUID and Vector3. Your own bot puts them to work.

The rest are the layers under sl, and what the commands are made of: client is the connection to slgod, agent the connection to the grid, and msg the grid's messages.

Where the pages are

The package pages are made when the handbook is folded into one file, so they are in that file and not in this directory:

$ python3 handbook/bundle.py

Go makes them, so that needs Go, and the first time it needs the network. In a checkout, the same documentation is a command away. go doc ./sl prints a package, go doc ./sl Session.Say prints one method, and go doc -http ./sl shows the pages in a browser.

How these pages are made

  • From the source, as it is built. bundle.py runs go doc -http, which serves pkgsite's pages for this checkout, and keeps the documentation part of each. So the pages say what the comments said at the commit in the footer.
  • Links. A type from another package here goes to its page. One from the standard library, or a module slgo uses, goes to pkg.go.dev. A declaration's name goes to its source on GitHub, at the same commit.
  • Left out: msg's message structures. They are generated from Linden Lab's message template: nearly fourteen hundred, each one line of documentation and the same three methods. A link to one goes to its line in the generated file.
  • Left out: proto/slgov1 and proto/scriptv1. They are the Go generated from proto/slgo.proto and proto/script.proto, the messages between a client and slgod. sl exposes none of it. client, the layer under sl, does, and a link from its page goes to the declaration's line in the generated code. Read the .proto files for the definitions.
