slgo handbook · setting up and keeping it running

Second Life, from a terminal

slgo is a handful of programs that share one idea: a daemon keeps your avatar logged in, and everything else comes and goes around it. This handbook gets those programs running, on one machine or spread over several.

This handbook is for the slgo in this checkout. slsh --version says which one you have.

The pieces

You only ever need the first two. Everything else is optional and can be added later without starting over.

ProgramWhat it doesWhere it runs
slgodThe daemon. Logs one or more avatars in and keeps them there. Holds the passwords. Listens for clients on TCP port 7807.One machine that stays on: a desktop, a small server, a Mac mini.
slshThe shell you type into. Chat, move, look at objects, manage inventory. Closing it leaves the avatar in-world.The slgod machine, or any machine that can reach it.
slbotdA bot that drives an avatar held by slgod. Takes commands by instant message and, with a language model, can hold a conversation.The slgod machine or a machine of its own.
llama-serverllama.cpp's model server. Not part of slgo. slbotd needs it only for conversation.Wherever there is a GPU or enough memory.
sl-hostPrints the address of the slgod machine for whichever network your laptop is on now.Only a client machine that moves between networks.
slrun, slbenchRun a script against an avatar; measure one. They connect just like slsh.Same as slsh.

The two things every connection needs

Every client reaches slgod on TCP port 7807, over TLS, and proves itself with one shared secret: the file ~/.config/slgod/secret. The same file must be on every machine that runs a client. There are no per-user accounts and no certificates to copy.

    How a client finds slgod

    Every client (slsh, slrun, slbench, slbotd) asks the same questions in the same order and stops at the first answer. Most setup problems are one of these steps answering when you didn't expect it to.

    1. --addr HOST:PORT on the command line.
    2. addr = in the client's config file (slsh: ~/.config/slsh/config).
    3. sl-host, if it is on your $PATH. The client tells it which profile it wants, and adds port 7807 to its answer unless the answer names a port. If it fails, the client stops here with an error. It does not fall back.
    4. localhost:7807.

    A common first stumble

    go install ./cmd/... installs sl-host too. Once it is on your path, clients run it, and without its rules file every client fails with sl-host: cannot read ~/.config/sl-host. If slgod is on the same machine, delete the sl-host binary, then run rehash (csh, zsh) or hash -r (sh, bash). More on sl-host.
