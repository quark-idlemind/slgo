Quick start · slsh's how, with a model

slsh with a language model

slsh's how turns a question in your own words into the command that does it. It works with nothing installed. With a small language model beside it, it understands far more ways of asking.

~10 min

What how does, with and without a model

Type a question at the slsh prompt:

/$ how do I make where I am standing my home

Without a model, slsh looks the words up in an index of every command's usage line, description and manual page. The index is built into slsh, so it always matches the commands you have. You get the best-matching commands with their descriptions and examples, under a first line that begins From the index alone and says why no model was asked. This needs nothing installed, and is often enough when your words are close to the manual's.

With a model, those best matches and the parts of their pages that matched are shown to the model, which picks the one that does the job. The answer is a line to type, the reason, and the sentence from that command's manual page that says so. slsh checks the suggestion first: it must be a real command with flags that command takes, and the quoted sentence must really be in its page. A suggestion that fails is dropped. how never runs anything.

A model is what makes questions phrased nothing like the manual work, such as the one above.

What you need

  • A server that speaks the OpenAI-style /v1/chat/completions: Ollama (the simplest) or llama.cpp's llama-server.
  • A small model, a few billion parameters. It can run on the same machine as slsh. slsh's guide recommends qwen3.5:4b-q4_K_M under Ollama.
  • No account and no API key. slsh sends no key, so hosted services that need one (OpenAI, Anthropic and the like) cannot be used directly.

The model runs wherever slsh can reach it over HTTP. That is usually the computer you type on, whether or not slgod runs there too.

Set it up with Ollama

  1. Install Ollama and start it

    Follow Ollama's own instructions for your system at ollama.com/download. On macOS that is an application you open; on Linux it is usually installed as a service that starts by itself. Either way it listens on 127.0.0.1:11434. These install steps are Ollama's, not slgo's, and are not repeated here.

  2. Fetch the model

    $ ollama pull qwen3.5:4b-q4_K_M

    The -q4_K_M matters. how asks the server for an answer in a fixed format (a JSON schema), and the default qwen3.5:4b is, on a Mac with Ollama 0.40.0 as measured, an MLX build, which refuses that with 501 Not Implemented: structured output is unavailable. ollama show on the model gives its quantization (nvfp4 is MLX), and ollama ps its runner (llamacpp works, mlx does not). Tags ending -q4_K_M or -q8_0 are GGUF builds; -mlx, -nvfp4 and -mxfp8 are MLX.

  3. Tell slsh where it is

    At the slsh prompt. Each set is saved in ~/.config/slsh/config, so this is done once.

    /$ set how_url http://127.0.0.1:11434
/$ set how_model qwen3.5:4b-q4_K_M
/$ set how_extra '{"reasoning_effort": "none"}'

    The last line matters for Qwen3 and Qwen3.5 models, which otherwise reason at length before answering. slsh's guide measured one taking about 30 seconds with reasoning on against 0.3 seconds with it off, and a smaller one returning nothing at all. The single quotes are needed: this is slsh's own prompt, and it takes double quotes off a word the way a shell does.

  4. Ask

    /$ how do I make where I am standing my home

    If the first line still begins From the index alone, the words in brackets after it say why. See When it does not use the model.

The settings

SettingDefaultWhat it does
how_urlempty: no modelThe server, with http:// or https:// in front. A trailing / or /v1 is ignored.
how_modelemptyThe model's name. Ollama needs it; llama-server ignores it.
how_slotempty: the server choosesA llama-server slot to use.
how_timeout2 minutesHow long to wait for the whole answer, like 45s.
how_extraemptyA JSON object added to every request, for what one model needs.

how -i answers from the index alone for one question, and how -r also shows what the model suggested and slsh dropped, with the reason.

Using llama-server instead

Point how_url at it and leave how_model empty:

/$ set how_url http://127.0.0.1:8080

Give each slot room. how keeps its prompt to about three thousand tokens and allows the reply 512. llama-server divides -c among its -np slots, so -c 8192 -np 4 leaves 2048 a slot, which is too small; 4096 a slot is enough. That figure is worked out from measured prompt sizes, not measured itself.

Sharing slbotd's llama-server

It works, and saves running a second model, but slbotd uses every slot the server has and keeps each conversation's context cached in its slot. A how question overwrites whichever slot it lands in, and slbotd's next reply there starts cold: seconds instead of a fraction of one, by slbotd's own measurements. A separate small model under Ollama avoids that. Setting up llama-server itself is covered on Bot + LLM.

What is sent to the model

Only the question as you typed it, and excerpts from slsh's own manual pages. No avatar name, region, inventory, chat or settings. The request goes over plain HTTP with no authentication, so keep the model on the same machine or reach it through a tunnel; see Security.

When it does not use the model

The first line of the answer says why, in brackets after From the index alone.

how_url is not set
No model is configured. That is the default (more); follow the steps above.
the server did not answer, or timed out
Check the server is running and the address is right: open http://127.0.0.1:11434 in a browser for Ollama. A first question after starting Ollama can be slow while the model loads.
the model cannot keep to how's answer format (structured output)
Ollama's MLX build of the model, which on a Mac is the default tag, refuses the schema how sends. Pull a GGUF tag such as qwen3.5:4b-q4_K_M and set how_model to it (the steps above).
slsh will not start after set how_url or set how_extra
The value in the config file is not one slsh accepts: an address without http://, or how_extra that is not a JSON object. The error names the line. See Troubleshooting.
