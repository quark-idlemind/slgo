Guide · writing a program

Your own bot

slsh and slbotd are Go programs built on slgo's sl package, and a program of your own can use it the same way. This page builds a shop greeter one step at a time. It greets people who arrive, remembers who it has greeted, answers questions in local chat and by IM, and hands out a gift.

~1 hour

What you will build

The greeter drives an avatar that slgod holds. Every few seconds it looks around. When somebody new comes within 20 metres, it turns to face them, greets them by name in local chat and offers them a gift. Anyone who says info nearby, or sends it by IM, is told where they are. The greeter keeps the list of people it has greeted in a file, so a restart does not greet the whole shop again.

This is what a visitor received when the greeter was tested on 25 September 2026. A small program attached to the visitor's avatar recorded it. The lines marked >> are what the visitor did. The names of the place are invented.

How your program reaches the avatar

  • slgod holds the avatar and speaks the grid's protocol. Your program attaches to slgod the way slsh does: over TLS on port 7807, proving itself with the shared secret. The sl package finds the secret file the same way every client does (rules).
  • The avatar outlives your program. When the program stops, crashes or is rebuilt, the avatar stays logged in. Several programs can attach to one avatar at once, so you can watch it in slsh while your bot runs.
  • A call waits until it can see the result. Rez returns the object it made, and Sit returns once the avatar is seated. Where the grid gives no reply, the package watches for the effect, and a call that could not confirm what it did returns an error saying so. Chat and IMs are acknowledged by nothing, so Say and SendIM return once the message is on its way. Every call takes a context and can fail.
  • What the grid tells the avatar arrives on channels. You subscribe to chat and IMs and read them in a loop. What can arrive lists every kind, and What a bot can do lists the actions.
  • There is also a way without slgod. sl.LoginDirect logs the avatar in from your program. The avatar then logs out when the program exits. Everything after the login is the same.

Before you start

  • A running slgod holding the bot's avatar. This page calls the profile greeter and its avatar Mirkwin Resident. Making a profile for a bot is step 1 of Adding slbotd. You do not need slbotd itself.
  • The slgo checkout slgod was built from, and Go 1.26.1 or newer. Build your bot against that same tree, because slgod refuses a client built from an older one.
  • slsh, to put the gift in the bot's inventory in step 8.
  • A place for the bot to stand, and the land owner's agreement to run a greeter there.

The grid says it is a bot

In testing, the first IM the greeter sent a visitor arrived with this in front of it (the avatar's name is invented):

Build it

  1. Make a module beside the checkout

    Make a directory for the program next to your slgo checkout, and point the new module at that checkout:

    $ mkdir greeter
$ cd greeter
$ go mod init example.com/greeter
$ go mod edit -replace github.com/quark-idlemind/slgo=../slgo

    The replace line builds your program from the same tree as your slgod. The path is relative to the greeter directory, so change ../slgo if your checkout is somewhere else. The module name example.com/greeter is yours to choose.

    To skip the typing, run the finished greeter from inside the checkout instead: go run ./examples/greeter with the flags from step 9.

  2. Connect

    Put this in main.go. It attaches to the avatar slgod holds under the profile greeter, and prints where it is:

    greeter/main.go
    package main

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/quark-idlemind/slgo/sl"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
	defer cancel()

	// Attach to the avatar slgod holds under the profile "greeter".
	s, err := sl.Dial(ctx, "localhost:7807", "greeter")
	if err != nil {
		log.Fatal(err)
	}
	defer s.Close()

	where, err := s.Where(ctx)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("%s is in %s at %.0f, %.0f, %.0f\n", s.Info().AvatarName,
		where.Region, where.Position.X, where.Position.Y, where.Position.Z)
}

    go mod tidy finds the package in your checkout and records it. Then run the program:

    $ go mod tidy

$ go run .

    That output is from the test, with the names invented.

    • sl.Dial takes slgod's address and a profile name. An empty name takes $SLGO_AGENT if it is set, and otherwise the session slgod has held longest.
    • Unlike the programs in the checkout, it does not ask sl-host where slgod is. Your program is told the address.
    • If it fails, the error is the one slsh would print, and Troubleshooting has them.

    From here on, main.go is the finished greeter. Copy the whole of examples/greeter/main.go over it now, and read on for what each part does.

  3. Listen

    A bot is a loop that waits for something to happen and deals with it. In this package, what happens arrives on Go channels. You subscribe to each kind and select over them:

    examples/greeter/main.go · listen
    // listen is the event loop.  Everything the bot does starts here, and
// runs one thing at a time.
func (g *greeter) listen(ctx context.Context) error {
	// Step 3: subscribe before doing anything else, so that nothing
	// said in between is missed.  Local chat from avatars only, at the
	// three volumes a person speaks at; every kind of IM.
	chat := g.s.Chat(sl.ChatFilter{
		SourceTypes: []uint8{sl.SourceAgent},
		Types:       []uint8{sl.ChatWhisper, sl.ChatSay, sl.ChatShout},
	}, 0)
	defer g.s.StopChat(chat)
	ims := g.s.IMs(0)
	defer g.s.StopIMs(ims)

	// Step 4: nothing announces an arrival, so look around on a timer.
	tick := time.NewTicker(g.o.every)
	defer tick.Stop()
	g.look(ctx)

	for {
		select {
		case <-ctx.Done():
			log.Printf("stopping; the avatar is still logged in")
			return nil
		case <-g.s.Done():
			return fmt.Errorf("the connection to slgod ended: %v", g.s.Err())
		case l, ok := <-chat:
			if !ok {
				return errors.New("the chat subscription ended")
			}
			g.heard(ctx, l)
		case im, ok := <-ims:
			if !ok {
				return errors.New("the IM subscription ended")
			}
			g.told(ctx, im)
		case <-tick.C:
			g.look(ctx)
		}
	}
}
    • Subscribe first. A subscription hears what arrives after it is made, and nothing earlier.
    • The filter here hears avatars only, at the three volumes a person speaks at. Without it you also get objects talking, script errors and typing notices.
    • Each channel has a buffer, 64 by default. If your loop falls behind and a buffer fills, new items are dropped rather than holding up the session. ChatDropped and IMsDropped count them. Keep each handler short.
    • s.Done() closes when the connection to slgod ends. The program then exits with an error, and a service manager can start it again.
    • ctx is cancelled by Ctrl-C or SIGTERM, which main arranges. The avatar stays logged in either way.
    • One handler runs at a time. That keeps the state simple, and nothing in this program needs a lock.

  4. Notice who arrives

    Nothing on the grid announces that somebody has walked in. So the bot looks around every few seconds, and compares what it sees with the last look:

    examples/greeter/main.go · look
    // look finds who is within reach, and deals with whoever has just
// arrived.
func (g *greeter) look(ctx context.Context) {
	people, err := g.s.Nearby(ctx)
	if err != nil {
		log.Printf("cannot see who is here: %v", err)
		return
	}
	now := map[msg.UUID]bool{}
	for _, p := range people {
		// Distance is -1 for somebody seated on something the region
		// has not described, who is here but cannot be placed.
		if p.Distance < 0 || float64(p.Distance) > g.o.radius {
			continue
		}
		// Nearby puts a shortened id where a name has not arrived
		// yet.  Wait for the name rather than greet a number: it is
		// usually there by the next look.
		name := g.s.Name(p.ID)
		if name == "" {
			continue
		}
		now[p.ID] = true
		if !g.here[p.ID] {
			g.arrived(ctx, p, name)
		}
	}
	g.here = now
}
    • Nearby lists the other avatars in the region, nearest first, with a distance in metres. It asks slgod, which has been listening since before your program started, so people who were already there are included.
    • It is cheap. Measured on 25 September 2026, with the program and slgod on one Mac and 808 objects known in the region: 108 ms for the first call, then 2 to 3 ms.
    • A name reaches the avatar a moment after the person does. Until it arrives, Nearby shows a shortened uuid, and the greeter waits for the next look rather than greet a number.
    • here is who was in reach at the last look. Anybody in reach now who was not there then has just arrived. This was tested by teleporting the bot away and back, with -every 2s. On its return, the next look found the three people there and greeted the one it had not met.

  5. Remember who was greeted

    An arrival is looked up in the memory first:

    examples/greeter/main.go · arrived
    // arrived decides what to say to somebody who has just come within
// reach: a greeting if they are new, a welcome back if they have been
// away long enough, and nothing otherwise.
func (g *greeter) arrived(ctx context.Context, p sl.Person, name string) {
	// Step 5: remember people by uuid.  A name is what is shown; the
	// uuid is who they are.
	id := p.ID.String()
	v := g.mem.Visitors[id]
	switch {
	case v == nil:
		g.greet(ctx, p, name, false)
		v = &visitor{Name: name, First: time.Now()}
		g.mem.Visitors[id] = v
	case g.o.again > 0 && time.Since(v.Last) >= g.o.again:
		g.greet(ctx, p, name, true)
	default:
		log.Printf("%s is here again; greeted on %s", name, v.First.Format(time.DateOnly))
	}
	v.Last = time.Now()
	if err := g.mem.save(); err != nil {
		log.Printf("cannot save %s: %v", g.o.memory, err)
	}
}

    The memory is a JSON file, read at startup and written after every arrival:

    examples/greeter/main.go · visitor, memory, loadMemory, save
    // visitor is one person the greeter has greeted.
type visitor struct {
	Name  string    `json:"name"`
	First time.Time `json:"first"` // when they were first greeted
	Last  time.Time `json:"last"`  // when they last came within reach
}

// memory is everyone greeted, by uuid, kept in a file so that a restart
// does not greet the whole shop again.
type memory struct {
	path     string
	Visitors map[string]*visitor `json:"visitors"`
}

// loadMemory reads the file, or starts an empty memory if there is none.
func loadMemory(path string) (*memory, error) {
	m := &memory{path: path}
	b, err := os.ReadFile(path)
	switch {
	case errors.Is(err, os.ErrNotExist):
		// Nobody greeted yet.
	case err != nil:
		return nil, err
	default:
		if err := json.Unmarshal(b, m); err != nil {
			return nil, fmt.Errorf("%s: %w", path, err)
		}
	}
	if m.Visitors == nil {
		m.Visitors = map[string]*visitor{}
	}
	return m, nil
}

// save writes the whole file under a new name and then renames it over
// the old one, so that a crash part way leaves the last good copy
// rather than half of one.  Mode 600, because it names everybody who
// came in.
func (m *memory) save() error {
	b, err := json.MarshalIndent(m, "", "  ")
	if err != nil {
		return err
	}
	tmp := m.path + ".new"
	if err := os.WriteFile(tmp, b, 0o600); err != nil {
		return err
	}
	return os.Rename(tmp, m.path)
}
    • People are keyed by uuid. The uuid is who somebody is; the name is kept only so that you can read the file.
    • save writes a new file and renames it over the old one. A crash part way through leaves the last good copy.
    • Mode 600, because the file names everybody who came in.
    • Leaving somebody out. To keep the greeter away from somebody, your staff for example, put their uuid in the file before it starts. That is how the tests on this page left two avatars alone.

  6. Greet

    examples/greeter/main.go · greet
    // greet says hello in local chat, and offers somebody new the gift.
func (g *greeter) greet(ctx context.Context, p sl.Person, name string, back bool) {
	// Step 6: act.  Turn to face them first.  It does not matter if
	// that fails, so it is only logged.
	if _, err := g.s.Face(ctx, p.Position); err != nil {
		log.Printf("cannot face %s: %v", name, err)
	}

	first := strings.Fields(name)[0]
	line := fmt.Sprintf("Welcome back, %s!", first)
	if !back {
		place, _ := g.land(ctx)
		line = fmt.Sprintf("Hello %s, welcome to %s!", first, place)
		// Step 8: the gift.  It is an offer: they have to accept it.
		if g.gift != nil {
			err := g.s.GiveToAvatar(ctx, p.ID, g.gift.ID, g.gift.Name, int8(g.gift.Type))
			if err != nil {
				log.Printf("cannot offer %s to %s: %v", g.gift.Name, name, err)
			} else {
				log.Printf("offered %s to %s", g.gift.Name, name)
				line += " I have sent you a " + g.gift.Name + "."
			}
		}
	}
	line += " Say info, or IM me info, to hear about this place."
	if err := g.s.Say(ctx, line, 0); err != nil {
		log.Printf("cannot greet %s: %v", name, err)
		return
	}
	log.Printf("greeted %s", name)
}
    • Face turns the avatar toward a place in the region without moving it. Move walks there; see What a bot can do.
    • Say puts a line in local chat on channel 0. SayAs does the same with sl.ChatWhisper or sl.ChatShout.
    • The greeting uses the first word of the name. For a newer account the name is the username followed by Resident.
    • With -again set, somebody away longer than that is welcomed back instead, without a second gift. From the test, with -again 24h and a last visit two days before: Welcome back, Quark! Say info, or IM me info, to hear about this place.

  7. Answer questions

    A line of local chat goes to heard, and an IM goes to told:

    examples/greeter/main.go · heard, told, tooSoon, asksForInfo
    // heard is one line of local chat from an avatar.
func (g *greeter) heard(ctx context.Context, l sl.Line) {
	// Step 7: answer.  Skip anything this avatar said itself.
	if l.Source == g.s.Me() || l.Mine {
		return
	}
	if !asksForInfo(l.Text) || tooSoon(g.answeredNearby, l.Source) {
		return
	}
	if err := g.s.Say(ctx, g.info(ctx), 0); err != nil {
		log.Printf("cannot answer %s: %v", l.From, err)
		return
	}
	log.Printf("told %s about this place, in local chat", l.From)
}

// told is one instant message.
func (g *greeter) told(ctx context.Context, im *sl.IM) {
	// An IM can be a dozen kinds of thing.  Conversation is true only
	// for somebody writing to this avatar: not a typing notice, a
	// group message, an offer, or this avatar's own words from another
	// client.
	if !im.Conversation() {
		return
	}
	var reply string
	switch {
	case asksForInfo(im.Text):
		if tooSoon(g.answeredIM, im.From) {
			return
		}
		reply = g.info(ctx)
	case time.Since(g.pointed[im.From]) > time.Hour:
		// Anything else gets one pointer an hour, and then silence.
		// Answering every IM is how two bots talk to each other
		// until somebody notices.
		g.pointed[im.From] = time.Now()
		reply = "I am this shop's greeter, and a bot. IM me info to hear about this place."
	default:
		return
	}
	if err := g.s.SendIM(ctx, im.From, reply); err != nil {
		log.Printf("cannot answer %s: %v", im.FromName, err)
		return
	}
	log.Printf("answered an IM from %s", im.FromName)
}

// tooSoon is whether this person was given the information in the last
// half minute, and notes that they are being given it now if not.
func tooSoon(last map[msg.UUID]time.Time, who msg.UUID) bool {
	if time.Since(last[who]) < 30*time.Second {
		return true
	}
	last[who] = time.Now()
	return false
}

// asksForInfo is whether a line asks for the information: the word
// info on its own, in any case, with or without a question mark.
func asksForInfo(text string) bool {
	t := strings.ToLower(strings.TrimSpace(text))
	return strings.TrimRight(t, "?!. ") == "info"
}

    Both answer with the same text, made from what the land says about itself:

    examples/greeter/main.go · info, land
    // info is the answer to "info": where this is, in the land's own words.
func (g *greeter) info(ctx context.Context) string {
	name, desc := g.land(ctx)
	text := "This is " + name
	if where, err := g.s.Where(ctx); err == nil {
		text += ", in " + where.Region
	}
	text += "."
	if desc != "" {
		text += " " + desc
	}
	return text
}

// land is the parcel's name and description, which its owner sets in a
// viewer under About Land.
func (g *greeter) land(ctx context.Context) (name, desc string) {
	p, err := g.s.Parcel(ctx, 10*time.Second)
	if err != nil {
		log.Printf("cannot read the parcel: %v", err)
		return "the shop", ""
	}
	return p.Name, p.Desc
}
    • Skip your own words. The grid sends the avatar what it said itself. Measured: a line the bot said in local chat arrived on its own subscription, from s.Me(). A bot that answers everything it hears would answer itself.
    • Answer only conversation. An IM can be a dozen kinds of thing: typing notices, group chat, inventory and teleport offers. Conversation() is true only for a person writing to this avatar. It is false for what this avatar sent from another client, which arrives marked Mine.
    • Limit what you say. The information goes to one person at most once in 30 seconds, counted separately nearby and by IM. Any other IM gets one pointer an hour, then silence. In testing, the visitor's avatar was itself run by slbotd with a language model, which sent the greeter two replies within four seconds of the pointer. The greeter said nothing more. Without the limit, the two would have talked until somebody stopped one of them.
    • The land's own words. The parcel name and description are what the owner sets under About Land in a viewer. The test parcel had no description, so the answer was only the name and the region.

  8. Hand out a gift

    Put the gift in a folder at the top of the bot's inventory. With slsh, attached to the bot's avatar, a notecard made from a text file will do:

    $ slsh -a greeter
/$ mkdir Greeter
/$ new --from welcome-kit.txt "Greeter/Welcome Kit"

    The greeter finds it at startup, and checks it can be given more than once:

    examples/greeter/main.go · findGift
    // findGift finds the gift in a folder at the top of the bot's inventory,
// and checks that it can be given away more than once.
func findGift(ctx context.Context, s *sl.Session, folder, name string) (*sl.Item, error) {
	f, err := s.Folder(ctx, folder)
	if err != nil {
		return nil, err
	}
	it, err := s.FindItem(ctx, f, name)
	if err != nil {
		return nil, err
	}
	// Without transfer it cannot be given at all.  Without copy it can
	// be given once: the first visitor to accept takes the only one.
	if it.OwnerMask&sl.PermTransfer == 0 {
		return nil, fmt.Errorf("%s is no-transfer, so it cannot be given", name)
	}
	if it.OwnerMask&sl.PermCopy == 0 {
		return nil, fmt.Errorf("%s is no-copy, so only the first visitor would get one", name)
	}
	return it, nil
}
    • Permissions. An item that is not transferable cannot be given at all. One that is not copyable can be given once, and the first visitor to accept takes the only one. The greeter refuses to start with either, rather than find out from a visitor.
    • GiveToAvatar is an offer. The visitor's viewer asks them to accept or decline, and nothing tells the bot which they chose. In the test the offer arrived in the same second as the greeting.
    • An offer nobody answers stays pending on the visitor's side.

What can arrive

The greeter reads local chat and IMs. These are all the kinds of thing a session can hear, and how to get each one. s is the *sl.Session.

What a bot can do

Every action is a method on the session. These are the ones a bot reaches for first. Run go doc ./sl in the checkout for the rest. Each call's comment says what it waits for and what it cannot tell.

ToCalls
TalkSay, SayAs (whisper, say or shout, on any channel), SendIM, Typing
MoveMove (walk to a place, with progress), Face, Halt, TeleportLocal, GoHome, Sit, SitOnGround, Stand
Find and use objectsObjectsNamed, AllObjects, Properties, Touch
Deal with peopleNearby, Lookup (by name), Names, Profile, OfferTeleport, OfferFriendship, InviteToGroup
Use inventoryListInventory, Folder, FindItem, GiveToAvatar, CreateFolder, RezFromInventory, Wear
Know the placeWhere, Region, Parcel, ParcelAt
Share the avatarLock, TryLock, Unlock: a name that only one program may hold at a time

Every one of them takes a context and returns an error. A bot that runs for weeks will meet each error sooner or later, so log it and carry on unless it means the session is gone.

Things you would not guess

  • Your own chat comes back. Measured, as in step 7.
  • The grid marks the bot's IMs. See Before you start.
  • Where is approximate. Between arrivals it follows the grid's coarse location updates, which carry whole metres. Above 1020 metres they carry no height, so the height stays at what it was when the avatar arrived (from the code). Measured: after a short walk left the bot at 4001.2 metres, Where still said 4004. Nearby measures distances from it, so leave a few metres to spare in a radius.
  • Names arrive late. See step 4.
  • A gift is only an offer. See step 8.
  • Everyone present at startup counts as arriving. See step 9.

Keeping it running

  • Run it as a service. The launchd and systemd templates for slbotd fit with the program's path and flags in place of slbotd's. That has not been tried with the greeter. Give -memory an absolute path, because a service's working directory is not yours.
  • When the connection to slgod ends, when slgod restarts for example, the greeter exits with an error. Restart=on-failure or KeepAlive starts it again, and the memory file means nobody is greeted twice.
  • When the avatar is logged out on purpose, with slsh logout, the connection to slgod stays up and the program keeps waiting. slgod keeps a client's connection while the session under it comes and goes. That is from slbotd's code, and has not been tried with the greeter.
  • Attend, don't use. The greeter attaches with sl.DialWeak rather than sl.Dial. That tells slgod the program only attends the avatar, so slsh logout does not refuse on its account.
  • Two programs on one avatar both hear everything. If only one of them should act, have each take a lock with TryLock and act only while holding it. slgod frees a lock when its holder's connection ends.

Security

Your program uses the same shared secret as slsh, and the secret opens every avatar slgod holds. Treat the machine your bot runs on like the slgod machine. The security page says more.
