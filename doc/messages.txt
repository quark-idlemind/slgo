# Every message in message_template.msg, one per line, in the order the
# template lists them.
#
#   name                          dir  what it is for
#
# dir says which way it travels on a viewer's circuit:
#
#   out    viewer -> simulator
#   in     simulator -> viewer
#   both   goes both ways, or is sent by whichever end has something to say
#   int    Linden Lab's own machinery -- simulator to dataserver, space
#          server, launcher -- and never seen on a viewer's circuit
#
# Where the directions came from, in order of preference: the template's
# own "viewer -> sim" annotations, then where the viewer builds the
# message and where it registers a handler for it, then the Trusted flag,
# which says the simulator will not accept the message from a viewer at
# all.  The last resort was knowing the protocol, and that is also what
# settled the cases where the first three disagreed -- the viewer source
# contains both ends of some conversations, so grepping it alone will
# tell you the viewer "sends" UUIDNameReply.
#
# "retired" means the message is marked Deprecated, UDPDeprecated or
# UDPBlackListed in the template: the simulator will either ignore it or
# never send it, and the traffic has moved to a capability or the event
# queue.  Sending one is a way to be quietly ignored.
