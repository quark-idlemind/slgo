agents lists what the daemon has: a line for every session it is
holding, and a line for every profile it could bring up and has not.
It is the listing login and logout act on, and the name in the first
column is the name those two take -- the profile the daemon hosts an
avatar under, which is not the avatar's own name beside it.

The order is the daemon's and is not alphabetical.  The sessions come
first, longest held first, then whatever is not up.  A star marks the
first session, which is the one a command that names no avatar drives,
and a session this shell is attached to says so at the end of its line.
The two are often the same and do not have to be.

# What stands where the region would

A session that is up shows the region its avatar is in.  Anything else
shows its state instead, with the reason after it where there is one:

	hosted      logged in and serving
	connecting  a login is in flight; wait for it
	configured  a profile exists and nothing has asked for it
	stopped     deliberately down, and staying down
	failed      a login was tried and refused; the detail says how

The last three are what the listing is for.  Told only whether a
session is connected, a profile nobody has ever started and an avatar
somebody logged out an hour ago look identical -- and the second is not
a fault at all, it is somebody using that avatar in a viewer.

# Why the star sits on the oldest session

It moves only when the session it is on goes away.  Bringing another
avatar up does not move it, attaching does not move it, and a session
that drops and is reconnected keeps its place.  Nothing done casually
can change which avatar a bare command drives, which is the point: a
benchmark run against the wrong avatar is not an error, it is a
plausible number.  An avatar that has been logged out gives up its
place, so logging it back in puts it at the end of the queue rather
than at the head of it.

A shell that logged in for itself has no daemon to ask, and says so
with the one avatar it has.
