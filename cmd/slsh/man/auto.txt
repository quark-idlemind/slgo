auto is about the worn objects that slrun and slbench run their
scripts in.  With no flags it reports what this avatar has: how many of
the objects are worn, and therefore how much can run at once.  With -n
it sets that many up, and prints which object went to which slot.

Nothing else in this shell needs it.  It is here because the answer to
"why will only eight scripts run at a time" is a number nothing else
prints.

# Why the objects are kept rather than made

A run could make its own object and throw it away afterwards, and the
cost of that is not mainly the rezzing.  It is the script: installing
one into an object that has never held a script takes about eight
seconds, while replacing a script already there takes under one.  So
the objects are made once, worn, and left alone.

They are worn on the HUD points because nothing else wants those and
they are no part of how the avatar looks.  There are only eight of
them, so the first eight objects have one each and the rest double up
-- a point holds more than one object when the attaching asks to add
rather than to replace, which was measured rather than assumed.  That
is what the listing after -n is for: past the eighth slot the only way
to see the pool is arranged as intended is to read which point each one
landed on.

# All of them or none, out of one pool

A run asks for a NUMBER of objects and gets that many or none.  What it
asks for is the width of what it is doing: a program running scripts
wants one per script it runs at once, and a benchmark wants one per
division of each of its searches and three besides, which at slbench's
defaults is nineteen -- more than the twelve one avatar wears, so a
benchmark's objects usually come from several.

The pool they come out of is the daemon's rather than this avatar's.
Twelve is what each hosted avatar contributes to it, and a request for
nineteen is answered out of as many avatars as it takes; what this
command reports is one avatar's share.  Naming an avatar confines a run
to that share.

Handing objects out one at a time is on its own a deadlock -- three
runs each wanting four of twelve can hold three apiece and wait for a
fourth nobody will give back.  What prevents it is that a request is
decided whole.  One goroutine in the daemon owns the pool, holds no
locks, and settles a request in a single pass over what is free: all of
them or none.  A request that cannot be served takes nothing, so there
is nothing for it to give back, and it comes away with a channel to
wait on instead, closed when something is given back or added.  Nothing
is ever held while waiting for anything else, so there is no cycle to
deadlock on.

A run wanting many can in principle be stepped over by a stream of runs
wanting one.  Nothing prevents that, deliberately: these are programs
run by hand or from a script rather than a service under load, and the
queue drains.

# Setting up while something is running

-n takes this avatar's whole share before it does anything, and refuses
if any of it is busy.  Wearing things is not something to do underneath
a benchmark: an attach replaces what is on the point, and a run whose
object went away reports nothing useful about why it failed.

Getting fewer objects than were asked for is not a failure and does not
read as one.  Fewer objects means less at once, and the report says so
in those words.

# Examples

Ask what is there:

	auto
	8 auto objects worn, so 8 scripts at once or 2 benchmarks of 4
	auto -n 12 sets up the rest

The first line of that is the answer to the question at the top of this
page.  Its "benchmarks of 4" is a number slbench has outgrown -- four
was what its search took when that line was written -- so read the
count of scripts and not the count of benchmarks.  The second line is
the report's own advice, printed only while there is room to grow, and
the twelve in it is this avatar's whole share rather than a suggestion:
it is how many entries the list of points has.  Taking it:

	auto -n 12

See also: worn for the same objects as attachments, wear and detach for
moving one by hand, and agents for which avatar this is being asked of.
